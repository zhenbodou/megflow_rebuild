# Ch4.7 分流节点：先写清楚按地址路由

Bcast 把消息复制给多个输出，Merge 从多个输入收集消息，Demux 根据消息地址选择一个
输出。本节先手写原版静态 Demux 的单消息步骤，后续还需要字典端口宏、标签装配及
节点生命周期才能成为可在 TOML 中使用的完整内置节点。

## 1. 先决定数据结构

假设两个输出地址是 7 和 42。不能把它们直接当成 Vec 下标：地址可能很大，也不连续。
使用 `HashMap<u64, Sender>`，键是路由地址，值是真正向下游发送消息的端点。

选择地址来自信封的 `info().to_addr`，不是载荷中的某个字段。框架因此可以路由整数、
字符串或图像等不同载荷，不必解析它们的业务内容。

## 2. 对照原版单步行为

原版入口是 `flow-rs/src/node/demux.rs::Demux::exec`。取到一条消息后：

1. 读取 to_addr；没有地址就 panic，不能默默选择默认输出。
2. 按地址查输出表；没有匹配项就丢弃消息。
3. 找到匹配项就原样发送，并忽略下游发送错误。

“丢弃”在 Rust 中意味着消息离开作用域并释放，不需要额外调用销毁方法。
发送时移动整份 SealedEnvelope，没有创建新信封，所以元信息也随之保留。

静态 Demux 不将空载荷解释成删除路由。原版 DynDemux 的空载荷路径会涉及实例与任务
生命周期，它是另一套协议，不能把两个节点的名称相似当成行为相同。

## 3. 写出完整实验

新建 `code/flow-rs/examples/demux_steps.rs`，先写 route 函数，再在 main 中创建两个
容量为 1 的通道并填充路由表。完整代码如下：

```rust,ignore
{{#include ../../../code/flow-rs/examples/demux_steps.rs}}
```

在仓库根目录运行：

```sh
cargo run --manifest-path code/Cargo.toml -p flow-rs --example demux_steps --locked
```

程序逐个验证地址 42 收到字符串、partial_id 保留、未知地址 99 不产生输出、地址 7
的空载荷仍到达，以及目标接收端关闭后 route 能返回。

`outputs.get(&address)` 返回对 Sender 的借用，发送完成前可以继续借用它；不需要为
每条消息 clone 路由表。`.await.ok()` 将发送失败转换成随后丢弃的 Option，这里是保留
原版忽略错误的行为，不是通用的错误处理建议。

注意容量 1 并不允许无限连续发送。实验每次发送后及时取出目标消息；完整节点运行时
必须让下游同时运行，才能在队列满时继续前进。

## 4. 独立练习与下一步

将第一条消息的地址改为 7，修改接收端断言，确认不会广播给两个端口。再删除 to_addr，
观察缺地址失败。随后将未知地址 99 添加到输出表，验证原来丢弃的消息现在可以到达。
每次只修改一个条件，先写预测再运行。

这份实验没有注册 Demux，也没有绕过宏用数组顺序假装地址标签。完整实现还必须：
从 `#[outputs(out:{T0})]` 得到字典端口形态；从 `node:port:tag` 得到地址；Builder 按
标签装配端点映射；最后让 Demux 参与原版要求的控制与生命周期协议。这些都是本书
继续补齐的内容，不能将本节的 route 函数作为最终框架的交付终点。

先完成[宏第 11 课的端口语言实验](../macros/11-port-grammar.md)，理解如何把
`out:{T0}` 分别解析为字段名、字典形态和模板编号，再回来连接本节的路由表。

接着完成[带标签的构造器接线](ch07a-tagged-construction.md)，将 TOML 标签实际传入节点构造阶段。
