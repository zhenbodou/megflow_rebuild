# Ch2.0 宏从零开始：先会展开，再写 macro_rules!

本章只要求你会变量、函数、结构体和 `Vec`。你不需要先懂过程宏。
先完成本章，再读 Ch2.1 的手写节点，然后进入 Ch2.2。

## 1. 为什么已经有函数，还要宏

函数接收值。例如 `double(3)` 把整数交给函数。宏接收代码片段，
生成另一段代码，然后由编译器继续检查、编译。`println!` 后面的感叹号
表示宏调用；并不是“更强的函数”。

如果只是把数乘二，写函数最清楚。如果要为不同结构体生成字段、
为每个节点生成 `impl Node`，就需要生成代码，这才是 MegFlow 使用宏的理由。
生成的代码仍须遵守所有权、类型和借用规则，宏没有绕过检查的特权。

先手工展开下面这个宏：

```rust
macro_rules! twice {
    ($value:expr) => {{
        let value = $value;
        value + value
    }};
}
fn main() {
    assert_eq!(twice!(3), 6);
}
```

读法是：匹配一个表达式，给它起名 `$value`，把右侧模板放到调用位置。
`twice!(3)` 的结果相当于 `{ let value = 3; value + value }`。
外层花括号界定模板；内层花括号让生成结果成为一个块表达式。
块的最后一行没有分号，因此它的值就是宏表达式的值。

不能简单写 `$value + $value`：如果传入 `{ calls += 1; 3 }`，
它会执行两次。临时变量保证输入只求值一次。这里的加法只适用于
支持这种用法的类型；宏不是自动克隆任意对象的泛型函数。

## 2. 冒号后面的词是在匹配什么

| 写法 | 接受什么 | MegFlow 中的用途 |
| --- | --- | --- |
| `$name:ident` | 一个标识符，如 `inp` | 节点名、端口名 |
| `$ty:ty` | 类型，如 `Vec<String>` | 端口载荷类型 |
| `$value:expr` | 表达式，如 `1 + 2` | 容量、构造参数 |
| `$path:path` | 路径，如 `crate::nodes::Add` | 注册类型路径 |
| `$literal:literal` | 字面量，如 `"Add"` | 注册名 |
| `$item:item` | 完整定义，如 `struct A;` | 包装定义 |
| `$visibility:vis` | 可见性，也可以为空 | 保留 `pub` |
| `$tree:tt` | 一个 token 或一组带括号的 token | 逐步解析小语法 |

`ident` 是语法类别，不是 `String` 类型；宏匹配阶段也不知道变量的运行时值。
`tt` 不是任意长度字符串，匹配任意多个 token tree 要用重复。
更多类别、作用域和版本差异以 [Rust Reference 的声明宏章节](https://doc.rust-lang.org/reference/macros-by-example.html) 为准。

## 3. 重复：从一个端口变成任意多个

```rust
macro_rules! port_names {
    ($($name:ident),* $(,)?) => {
        &[$(stringify!($name)),*]
    };
}
fn main() {
    let names: &[&str] = port_names!(inp, out,);
    assert_eq!(names, &["inp", "out"]);
}
```

从里往外读：`$name:ident` 收一个名字，`$(...),*` 收零个或多个，
名字之间用逗号隔开。末尾 `$(,)?` 接受可选的尾逗号。
输出侧用相同的重复层级，为每个名字调用 `stringify!`，得到静态字符串。
这里没有运行时循环；两个名字在编译时就生成两个数组元素。

`*` 表示零次或多次，`+` 表示至少一次，`?` 表示至多一次。
若你需要拒绝空列表，把第一处 `*` 改成 `+`，再用空调用确认编译失败。

## 5. 名字、作用域和卫生性

卫生性讨论“生成代码中的名字到哪里找”。前面的 `value` 是宏内部临时变量，
调用者也有一个 `value` 时，不应靠字符串替换去理解它们。
声明宏有混合卫生性；不要因此推断所有标识符都绝对不会冲突。

要把声明宏提供给其他 crate，可使用 `#[macro_export]`，它会从定义 crate
的根导出宏。宏生成的代码需要调用本 crate 的公开辅助函数时，使用
`$crate::helper()`，避免依赖调用者给 crate 起的名字。
`$crate` 不会绕过私有性：跨 crate 使用时，辅助项仍必须可访问。

过程宏没有同样的 `$crate` 模板机制。当前节点宏生成 `flow_rs::...`，
因此依赖改名时需要额外处理；不能把这件事藏在“宏自动解决”里。

## 6. 从报错定位到展开结果

| 报错现象 | 先检查什么 | 修复思路 |
| --- | --- | --- |
| `no rules expected` | 实参是否符合匹配器 | `ident` 位置不要传字符串 |
| `local ambiguity` | 相邻重复是否争抢同一 token | 加明确分隔符，简化语法 |
| 重复深度不匹配 | 输出侧是否漏掉 `$()` | 保持变量的重复层级 |
| 类型或借用错误 | 手工展开后的代码 | 修复生成结果的类型或所有权 |
| 找不到宏 | 定义位置、模块路径、导入 | 先在同文件定义后调用 |

宏规则按顺序尝试，先放具体规则，再放宽泛规则。复杂 DSL 可以用递归
逐个消费 `tt`（常称 TT muncher），但先把语法写清楚再选择；它可能增加
编译成本，也会让错误定位更难。项目的端口语法接下来用 `syn::Parse`
实现，不要求新手先写递归解析器。

## 7. 练习和可检查答案

1. 把 `port_names!` 改为至少一个端口，空调用应编译失败；答案是将匹配列表的 `*` 改为 `+`，输出重复也对应改为 `+`。
2. 故意将 `twice!` 改成直接复制表达式，执行完整示例；`calls` 断言应失败，说明宏参数可能有副作用。
3. 给 `Settings` 增加 `enabled: bool`，在构造时填入 `true` 并断言。若只有构造处报缺字段，说明宏已经正确生成字段。
4. 手写 `node_struct!` 展开后的结构体并比较。只有能解释每个 token 的去向，才进入过程宏。

学完这里不代表精通了宏。后续必须继续掌握语法树、错误 span、泛型、
属性协作、下游编译测试和真实节点展开，才能独立维护 MegFlow 的宏系统。
