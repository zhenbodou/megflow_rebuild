# 前言

这本书带你**从零用 Rust 重写 MegFlow 引擎核心**。读完你将：

1. 吃透 MegFlow（算法仓赖以运行的 dataflow 框架）的每个模块；
2. 顺带补齐 Rust 的异步、trait 对象、过程宏、生命周期；
3. 逐步实现与原版 Rust 功能和业务逻辑一致的引擎；完成情况以验收账本为准。

本书的交付标准是：**初学者从空目录开始，按章节逐步开发；读完最后一章时，
完整 Rust MegFlow 框架已经由读者实现，并通过功能与业务逻辑的原版对照验收。**
涉及的知识点必须随开发步骤详细解释，不能把缺失实现留作“进阶探索”，也不能让读者
依赖尚未讲到的最终仓库代码才能继续。

每章都需要明确起点文件、逐步修改、完整可运行结果、排错方法和验收条件。
参考实现用于对照与排错，不代替教学过程。当前全书尚未满足这一标准，缺口见
[验收账本](part0/ch04-completeness-audit.md)。
请先读 [从看懂代码到独立开发](part0/ch05-learn-to-build.md)，了解学习和验收方法。

## 这本书怎么读

- **纵切、即时补 Rust**：按引擎真实模块顺序建（消息 → 节点/宏 → 注册表 → 配置 → 图 → 运行时 → 内置节点 → 子图 → 兼容），每进入一块，先用小练习补齐正好需要的 Rust 概念，再动手实现。
- **TDD、每章能跑**：每章「红 → 绿 → 重构」，结束时 `cargo build` + `cargo test` 必须全绿。
- **书与工程互相验证**：带完整文件路径的示例用对应命令验证；阶段性片段需要配合上下文，不能当作独立程序。当前仍有待补齐的逐章复现工作，见验收账本。

## 里程碑

- **Ch3.4**：端到端跑通 BinaryOp `1 + 2 == 3`（第一个完整框架）。
- **Ch5.1**：跑通一个 detector → tracker → alarm 风格的多节点/子图图。

## 目标与当前完成度

最终目标是完整 Rust 重构。目前正文和参考实现仍有核心子集限制，尚未达到
完整功能对齐。动态/共享子图、配置优化器、消息业务类型、Rust 服务插件等
仍须补齐，不因本地基础测试通过而视为完成。

请先读 [完整重构的验收账本](part0/ch04-completeness-audit.md)，了解每项差距、
原版源码证据和验收要求。Python 调用层可以不保留，Rust 业务能力不能随之删去。

宏学习从 [Ch2.0](macros/01-basics.md) 开始，随后逐步学习过程宏和相关 crate。
